<div class="bluf"><span class="lbl">Bottom line up front</span><br>
Run a simple, gated pipeline with an <b>objective exit criterion at every stage</b> — a deal only advances when the criterion is met, never on optimism. This keeps the forecast honest and shows exactly where deals stall. (Fittingly, you run this in SalesOps CRM itself — you use what you sell.)</div>

## Pipeline stages

| Stage | Exit criterion (must be true to advance) |
|---|---|
| 1. New lead | ICP-fit confirmed (Pack 06) |
| 2. Contacted | Two-way conversation happened |
| 3. Discovery done | 2+ pains quantified; economic buyer identified (Pack 09) |
| 4. Demo held | Prospect saw their workflow solved live |
| 5. Trial active | Data migrated; team using it by day 7 (Pack 12) |
| 6. Won | Contract signed via e-signature |
| — Lost / nurture | Reason logged (feeds win/loss learning, Pack 04) |

<div class="callout"><span class="lbl">Why exit criteria matter</span><br>
Stages defined by <b>evidence</b> ("prospect saw X"), not feeling ("seems keen"), make the forecast trustworthy and reveal the true bottleneck. If deals pile up at Stage 4→5, the problem is the trial start, not lead volume — and you fix the right thing.</div>

## Implication

This pipeline drives the KPI dashboard and forecasting (this Pack) and the SOPs (Pack 12). It is deliberately simple — a lean team needs clarity, not a 12-stage bureaucracy.
